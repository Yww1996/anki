## 对当前 Anki 的判断与优先级

### 1. 首页：让牌组列表成为主要内容

保留放大后的可读字号。减少顶部“Anki 学习空间”的品牌展示面积，牌组图标使用同一尺寸和线宽，默认低饱和；颜色用于选中态、队列状态和主要动作。当前牌组同时出现在上方学习卡片和下方列表，存在重复，建议将“开始学习”归入选中牌组的一行或紧凑工具区。待学为零时显示“今天已完成”，提供复习与管理入口，避免只有一个灰横线。

验收：常用窗口首屏能看到主要牌组和学习入口；主动作清楚；缩小窗口后不出现横向滚动。

### 2. 设置：按用户目的找选项

保留本轮缩小后的窗口和“复习算法”入口。以后可组织为“通用、学习与算法、外观、同步与账户、备份、进阶”。先呈现常用选项，复杂解释按需展开。算法切换继续调用上游设置逻辑，清楚表达 FSRS 开关对整个资料库生效，参数属于牌组预设。搜索可升级为跨分类搜索，结果显示所属分类。

验收：首次进入能找到算法和同步账户；切页不丢输入；内容滚动而底部完成按钮固定可见。

### 3. 同步：主窗口可见状态，必要时才弹窗

建议顶部同步入口表达“同步中、已同步、需要处理”状态，普通同步过程尽量不中断学习。点击状态后展开详情，显示集合与媒体的实际进度。仅在登录、冲突决策或需要重试时打开窗口。此项需要梳理上游后台任务和退出同步流程，不能只通过隐藏弹窗实现；业务改动与纯视觉调整分开验证。

验收：集合完成但媒体仍在同步时不提前宣告全部完成；取消和失败都有明确结果；不依赖虚构百分比。

### 4. 学习页：减少非学习操作

参考 IINA 对内容和控制的分工，题目/答案居中，评分区稳定，保留可发现的快捷键。管理、统计、编辑等保留入口但降低视觉重量。评分按钮始终可见，避免把关键操作仅放在悬停出现的控件里。

### 5. 卡片管理：适合分栏，首页不必三栏

参考妙言和 FSNotes 的列表与内容关系，将浏览、选择和预览连接起来。宽窗口可显示牌组/标签、列表、详情；窄窗口按当前操作切换面板，不把所有列挤小。

## 建议方向

以妙言/FSNotes 的内容布局为主，Ice 的设置组织和 IINA 的专注交互为辅。继续沿用已接入的 shadcn-svelte 控件，实现原生 Mac 的尺寸、层级和交互习惯。无需因此改写为 SwiftUI；先集中优化首页与设置，再处理涉及后台任务的同步状态。
